# Workflow: Development Delivery

1. **Readiness:** verify actual handoff access/version/approval; review scope, architecture, estimate, risks, conditions. No code.
2. **Planning:** milestones, epics, tasks, requirement/AC links, dependencies, deliverables, tests, owners, estimates; submit for approval.
3. **Implementation authorisation:** require explicit Human Engineering Lead approval; verify repo, branch, environment, access, scope.
4. **Implementation:** inspect existing code, make small reviewable changes, implement approved scope only, record evidence.
5. **Verification:** relevant unit/integration/API/UI/security/acceptance tests; report failures honestly.
6. **Release:** release notes, deployment/rollback plan; explicit production approval; verify actual deployment; human final acceptance.

Statuses: NOT STARTED, PLANNED, ASSIGNED, IN PROGRESS, BLOCKED, IN REVIEW, QA, COMPLETED. Only Development Manager exists currently; future specialist agents require approval.
